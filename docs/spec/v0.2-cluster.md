# disdetta v0.2 specification: cluster scan

Status: accepted (2026-10-14). Extends [v0.1](v0.1.md); everything in v0.1 still holds (rules, severity, confidence, impact, fingerprints, redaction, exit codes, JSON schema version 1 with additive fields only).

## 1. CLI

```
disdetta scan --cluster [--context NAME] [--kubeconfig FILE] [--namespace NS ...] [--read-helm-secrets]
              [--deny-exec-plugins] [--timeout DURATION]
              [--format table|json] [--fail-on ...] [--rule ...] [--config FILE]
```

- `--cluster` replaces the path argument; giving both is a usage error (exit 2).
- Default: all namespaces the identity can list. `--namespace` is repeatable.
- Kubeconfig resolution follows kubectl (`--kubeconfig`, `KUBECONFIG`, `~/.kube/config`), `--context` selects the context.
- `--deny-exec-plugins` refuses a kubeconfig whose selected user has an exec provider or an auth provider: client-go would run that program. The refusal is a usage error (exit 2) and happens before any plugin runs.
- `--timeout` is the **total time budget of the scan**, not the timeout of one list (default 30 s). The scan stops when the budget is spent and the report says the scan is incomplete.
- Ignore files: `--config` only (there is no scan root).

## 2. Read tiers

| Tier | Reads | Needs | Default |
| --- | --- | --- | --- |
| 1 | Pod templates of Deployment, StatefulSet, DaemonSet, ReplicaSet (only when not owned by a Deployment), Job (only when not owned by a CronJob), CronJob; standalone Pods (no controller owner); `status.containerStatuses[].imageID` of running Pods | `list` on those kinds | on |
| 2 | Chart origin from workload labels `helm.sh/chart` (`<chart>-<version>`) and `app.kubernetes.io/managed-by: Helm`, release from `meta.helm.sh/release-name` / `app.kubernetes.io/instance` | nothing more | on |
| 3 | Helm release Secrets (`type: helm.sh/release.v1`, label `owner=helm`, latest deployed revision per release): chart metadata (`name`, `version`, `home`, `sources`) and user-supplied values (`config`) | `list` on Secrets | **off**, `--read-helm-secrets` |

Tier 3 exists because `global.security.allowInsecureImages` is visible only in the user values; tiers 1-2 cannot see it. Its payload may contain credentials (threat model T2).

## 3. Findings from the cluster

Same rules as v0.1:
- container images (all containers, initContainers, ephemeralContainers) -> `DSD-IMG-00x`;
- tier 3 chart metadata pointing to `github.com/bitnami/charts` (or chart annotations listing Bitnami images) -> `DSD-CHT-002` for the release;
- tier 3 user values -> scanned with the v0.1 values detector (`DSD-CFG-001`, image triples, fallbacks).

Location for cluster findings: `path` = `cluster/<namespace>/<Kind>/<name>`, line and column 0. Additive field `resource`:
```json
{"context": "kind-dev", "namespace": "db", "kind": "StatefulSet", "name": "pg", "container": "postgresql", "release": "pg", "chart": "postgresql-16.4.0"}
```
`container` is empty for release-level findings. `release`/`chart` come from tier 2 or 3 when known.

Running image identity: when `imageID` shows a different registry than the spec image (mirror or pull-through cache), attribute `mirror` is added. `imageID` digests are never used to guess a tag.

Fingerprint: `path` above replaces the file path; `reference` and `occurrence` unchanged (occurrence ordered by kind, namespace, name, container).

Grouping: findings are not merged. The summary gains `releases` (number of distinct releases with at least one finding) and JSON gains a `groups` array: one entry per (namespace, release or workload), with its component, highest severity, highest impact and the fingerprints of its findings. Deterministic order: severity, impact, namespace, name.

## 4. Safety

- Only `get`/`list` verbs are ever issued. A test with a fake client asserts no other verb is used.
- Tier 3: base64 and gzip bounded (compressed payload cap 4 MiB, decompressed cap 32 MiB, ratio cap 100:1); a payload over a cap is `DSD-SCN-009` (error, incomplete). Decoded payloads live in memory only; `config` is scanned and discarded; no value reaches output, logs or diagnostics (only the reference itself, as in v0.1 section 6).
- Forbidden or failed list on a kind/namespace is `DSD-SCN-010` (warning when RBAC forbids, error otherwise) and the scan continues; a forbidden tier makes the report state which tier was incomplete. API errors never echo object content.
- The API server is untrusted for content, so the reads are bounded: the answer is never transparently decompressed, a response body is read through a hard limit of 64 MiB (`MaxListResponseBytes`), a list stops at 100000 items (`MaxItemsPerList`) or at 1000 pages (`MaxPagesPerList`), and a 3xx answer is refused instead of followed, so the bearer token never reaches the redirect target. An over-limit body is a `DSD-SCN-010` whose message names the limit; a cap that ends a list is a `DSD-SCN-005` whose message names the cap. No bound is a silent truncation and every bound leaves the report incomplete.
- The whole scan shares one deadline: `--timeout` is the total time budget of the scan. Each request is bounded by the smaller of the remaining budget and 30 s. When the budget is spent the scan stops cleanly, reports the objects it did read and one `DSD-SCN-005` diagnostic that says the scan is incomplete (exit code 3).
- The minimal RBAC is documented in `docs/cluster-rbac.md` with a ready ClusterRole for tiers 1-2 and a separate one for tier 3.

## 5. Diagnostics added

| Code | Level | Meaning |
| --- | --- | --- |
| `DSD-SCN-009` | error | Helm release payload over a size or ratio cap, or not decodable. |
| `DSD-SCN-010` | warning / error | List failed: forbidden (warning) or other API error (error). A response body over the 64 MiB limit is an error whose message names the limit. |
| `DSD-SCN-005` | warning | A cluster safety limit ended a read: the item cap, the page cap, or the total time budget of the scan. The scan is incomplete. |

## 6. Acceptance

- Unit tests on recorded API objects (`testdata/cluster/*.yaml`) through the fake clientset: every workload kind, owner filtering, tiers 2 and 3, caps, RBAC forbidden, redaction of Secret payloads (a planted password never appears in any output), verb assertion.
- Goldens (table + JSON) for a recorded cluster; JSON validated against the schema.
- A kind integration test (build tag `kind`, CI job on `main` and nightly) deploying a Bitnami chart with `bitnamilegacy` images and `allowInsecureImages=true`, asserting the expected rules with `--read-helm-secrets` and without.
