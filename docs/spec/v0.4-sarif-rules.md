# disdetta v0.4 specification: SARIF output and `rules`

Status: accepted (2026-10-14). Extends v0.1-v0.3. Closes issues #11 and #13.

## 1. `scan --format sarif`

SARIF 2.1.0 (https://docs.oasis-open.org/sarif/sarif/v2.1.0/sarif-v2.1.0.html), one `run`:

- `tool.driver`: `name: disdetta`, `version` from the build, `informationUri` the repository URL, `rules[]` = every finding rule (`DSD-CFG-001`, `DSD-IMG-001..004`, `DSD-CHT-001..002`) sorted by id, each with `id`, `name` (short kebab title), `shortDescription`, `fullDescription`, `helpUri` = `https://github.com/HarnageaGabriel/disdetta/blob/main/docs/diagnostics/<ID>.md`, `defaultConfiguration.level` (high -> `error`, medium -> `warning`, low -> `note`), `properties.tags` (`bitnami`, `security`, component when known is per result, not here).
- `results[]`, one per finding, in report order: `ruleId`, `ruleIndex`, `level` from severity, `message.text` = rule one-liner + reference (already redacted), `locations[0].physicalLocation.artifactLocation.uri` = the report path (slash-separated, relative to the scan root, `uriBaseId: "%SRCROOT%"`) and `region.startLine`/`startColumn` (1-based; omitted when 0, as for cluster findings, which use `logicalLocations` with `fullyQualifiedName` = the cluster path and `kind` = the resource kind), `partialFingerprints.disdettaFingerprint/v1` = the spec fingerprint, `properties`: `confidence`, `impact`, `component`, `attributes`.
- Scanner diagnostics (`DSD-SCN-*`) are not results. They go to `invocations[0].toolExecutionNotifications[]` with `descriptor.id`, `level` (error/warning/note from error/warning/info), `message.text`, `locations` when a path exists. `invocations[0].executionSuccessful` = scan complete, `exitCode` = the process exit code.
- `originalUriBaseIds.%SRCROOT%` is omitted (the consumer knows the checkout root).
- Deterministic: no timestamps, no absolute paths, no machine names; keys in a fixed order (struct-ordered JSON), indentation 2 spaces.
- Redaction: exactly the strings already allowed in table/JSON output.
- Ignored findings (spec v0.1 section 6) are not emitted as suppressed results; the count stays in `invocations[0].properties.ignored`.

Acceptance: golden SARIF per fixture; each golden validated against the SARIF 2.1.0 JSON schema vendored at `schemas/sarif-2.1.0.json` (use the OASIS schema from https://docs.oasis-open.org/sarif/sarif/v2.1.0/errata01/os/schemas/sarif-schema-2.1.0.json; if it cannot be fetched offline, commit a minimal structural schema of the fields above and mark `VERIFY:`); GitHub code scanning requires `ruleId`, `message.text`, a location with `uri` and `startLine` for file results.

## 2. `disdetta rules`

```
disdetta rules [--format table|json]
```

Prints every finding rule and every diagnostic from the registry in `internal/diag`, sorted by code: `CODE`, `KIND` (rule | diagnostic), `SEVERITY` (rules: high/medium/low) or `LEVEL` (diagnostics: error/warning/info), `TITLE`, `DOCS` (URL as above). JSON: `{"schemaVersion":"1","rules":[...]}` with the same fields (`schemas/rules-v1.json`). Exit 0. Deterministic, golden tests; the README lists the command.
